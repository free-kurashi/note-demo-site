# 読了の循環(デモ)

読んだ100円noteを note 公式の埋め込みカードで並べ、サイト主や読者が感想を書くたびに、世界地図のジグソーパズル(100ピース)が埋まっていくサイト。
公開先: https://free-kurashi.github.io/note-demo-site/ (GitHub Pages)。最終的には Cloudflare で公開する予定(後述)。

## いまできること(デモ版)

- note の記事を、note 公式の埋め込み(`https://note.com/embed/notes/<記事ID>` + 公式 `embed.js`)でカード表示
- **ページ上部に金額を表示**: 今ある合計金額 / サイト主の購入額 / サイト主のtip額 / 読者の皆さんの購入額 / 読者の皆さんのtip額(カードごとの金額表示はしない)
- **世界地図のジグソーパズル(100ピース)**: サイト主や読者が感想を書くたびにピースが1つ埋まる。どのピースが埋まるかはランダムで、重複しない(固定シードの並び順)。感想なしの金額だけの入力では埋まらない。100ピースそろうと世界地図の完成
- **使い方(チュートリアル)**: タイトル横の「使い方を見る」から、想定する利用方法と3ステップの手順を表示。「読者のアクションを試してみる」で、1枚目のカードの入力画面まで案内する
- カードのボタン
  - **noteで開く**: 記事を新しいタブで開く
  - **サイト主の感想**: サイト主の感想を表示
  - **読者の感想 (n)**: 読者の感想を1人ずつ閲覧(◀ 前の人 / 次の人 ▶)
  - **読者のアクション**: 名前(任意)・購入金額・tips額・感想を入力して記録

> デモ版の制限(画面でも、タイトル横の「デモ画面」バッジ、サイト主の感想ダイアログ、ページ下の注意書きで明示している)
> - 記事は `witty_minnow853` の公開記事19件(`public/entries.json`)。購入額・tips額・サイト主の感想は仮の値。
> - 「読者の感想」の一部(各記事1〜3人)はデモ用サンプル(`src/data/demo.ts`、固定シードで毎回同じ)。画面上も「(デモ)」と表示。
> - 読者のアクションの入力は、その人のブラウザ(localStorage)にだけ保存される。**他の人の入力とは合算されない**。パズルの進み具合も、この端末での入力分だけが加わる。

## サイト主の登録(Notion 連携)

Notion にデータベースを作り、次のプロパティを用意する(名前は完全一致)。

| プロパティ名 | 種類 | 内容 |
|---|---|---|
| (任意の名前) | タイトル | メモ用 |
| `noteのリンク` | URL | 例: https://note.com/xxx/n/nxxxxxxxxxxxx |
| `購入額` | 数値 | サイト主が購入した額(円) |
| `tips額` | 数値 | サイト主が贈った tips 額(円)。`tip額` でも可 |
| `感想` | テキスト | サイト主の感想 |

行を追加すると、最大30分後に一覧へ反映される(GitHub Actions が取り込んで再公開)。

### 初回設定(未実施)

1. https://www.notion.so/profile/integrations で「内部インテグレーション」を作成し、シークレットをコピー
2. 作成したデータベースの「…」→「接続」から、そのインテグレーションを追加
3. データベースURLの32桁がデータベースID
4. GitHub のこのリポジトリ → Settings → Secrets and variables → Actions に登録
   - `NOTION_TOKEN` = シークレット
   - `NOTION_DATABASE_ID` = 32桁のID

未設定の間は、コミット済みの `public/entries.json` を表示する(`scripts/sync-notion.mjs` は何もせず終了)。

## 構成

```
index.html               画面の骨組み(ダイアログ含む)
src/main.ts              画面の組み立て・ボタン処理・金額集計
src/ui/cards.ts          カード(埋め込み iframe + ボタン)
src/data/repository.ts   データ取得・保存(Entry / ReaderPost の型もここ)
src/data/demo.ts         デモ用の読者の感想
src/art/puzzle.ts        世界地図のジグソーパズル(d3-geo + world-atlas で地図を描き、100ピースに分割。感想の数だけランダムに埋める)
src/art/rng.ts           シード付き乱数
scripts/sync-notion.mjs  Notion → public/entries.json
public/entries.json      登録データ(Notion 未接続時の初期データ)
.github/workflows/       GitHub Pages へのデプロイ(30分ごと + push 時)
vite.config.ts           base を /note-demo-site/ に設定(Cloudflare では BASE_PATH=/)
```

データの出し入れは `src/data/repository.ts` に集約してあり、サーバー側に移すときはここを差し替える。

## 今後のメモ

### Cloudflare で公開するときの保存先(方針)

| データ | 保存先 | 理由 |
|---|---|---|
| サイト主の記事リンク・購入額・tips額・感想 | **Notion のまま** | サイト主が普段から手で入力する場所。Worker(Pages Functions)が Notion API で読み、短時間キャッシュ(KV など)する |
| 読者の金額・tips・感想 | **Cloudflare D1** | 読者が入力するたびに書き込み、全員分を集計する用途。Notion は書き込み回数・速度の制限があり、読者の入力が直接 Notion に入ってしまうので不向き |

- 構成案: Cloudflare Pages(静的サイト)+ Pages Functions(`/api/entries` = Notion 読み取り、`/api/readers` = D1 読み書き)+ D1。
- D1 の想定テーブル: `reader_posts(id, entry_id, name, review, purchase, tip, created_at)`。トップの合計は `SUM` で集計、カードの人数は `purchase > 0` / `tip > 0` の件数。
- Notion の API トークンは Cloudflare の Secrets に置く(GitHub Pages では秘密鍵を持てないため、移行が必要)。
- KV でも保存できるが、集計が面倒になるため D1 を推奨。
- 移行時の作業: `repository.ts` を API 呼び出しに差し替え → `BASE_PATH=/` でビルド → `wrangler login` / D1 作成 / Secrets 登録 → デプロイ。GitHub Actions の Notion 取り込みは不要になる。

### note の埋め込みと規約(確認結果)

「note ご利用規約」(総則・クリエイター規約・ユーザー規約・ポイント規約。第24版 2026-10-08)の本文を読んだ限りの整理。法的判断ではない。

**結論**: 埋め込み(iframe)やリンクを禁止する条文は見当たらない。ただし「問題ない」と言い切れる条文もない。自分の記事だけを並べる現状は懸念が小さい。他人の記事を並べる場合は下記の懸念点がある。

使ってよいと言える根拠
- 埋め込み・iframe・リンクを禁じる条文がない(総則13.1の禁止事項にもない)
- 総則13.1(1)の禁止は「複製・販売・出版・公衆送信…等、購読契約の範囲を超えた利用」。埋め込みは note.com のサーバーがカードを配信する形で、このサイトに記事を複製・保存していない
- note 自身が埋め込みを想定している(確認済みの事実): 埋め込みページが `X-Frame-Options: ALLOWALL`、`googlebot: indexifembedded` を返し、高さ調整用の公式 `embed.js` を配っている
- 著作権はクリエイターに帰属(総則3.2)。埋め込みは権利を移さず、クリックで note に移動する
- 自分の記事なら、13.1(1)の「クリエイターの承諾」は自分自身のもの

注意すべき根拠
- 13.1(1)の「購読契約の範囲を超えて利用」は包括的な表現。他人の有料記事のカード表示範囲が範囲内かは規約だけでは断定できない
- クリエイター規約に「外部サイトへの配信を許諾する」設定がある(note 自身の転載についての記述だが、著者が外部配信を制御する考え方がある)
- サーバー負荷: 総則13.1(7)「サービスの障害となる行為」、クリエイター規約10.1(7)「サーバーに過度に負担をかける場合」。iframe は遅延読み込み(`loading="lazy"`)にしており、件数が増えたらページ分割する
- `robots.txt` は `/embed/*` をクローラーに Disallow(自動巡回向け。閲覧者のブラウザが読み込む埋め込みとは別)
- **自己取引の禁止(総則13.1(9))**: 自分が販売するコンテンツを自分で購入する行為は禁止。サイト主の購入額を「自分の記事に対する購入」として扱わない。現在のデモは自分の記事だけで、購入額は仮の値(実際には購入していない)

### 他人の記事のリンクを貼る場合の懸念点

- **規約上の位置づけ**: 禁止条文は見当たらないが、13.1(1)の包括表現と有料記事のカード表示範囲は断定できない。事前に note サポートへ確認する(問い合わせ文案と回答の記録欄: [docs/note-support-inquiry.md](docs/note-support-inquiry.md))
- **著者の意向**: 事前連絡、外してほしいと言われたらすぐ削除する運用、連絡先のサイト明記
- **他人の記事に紐づく情報**: 読者の感想はその記事の著者の目に触れる。金額は記事ごとには表示せず、サイト全体の合計だけを出す方針(自己申告で note の実績ではないと明記し、「売上」と誤認させない)。売上の公開で購入を煽る行為はクリエイター規約10.1(3)で問題視されるため、購入を促す文言にしない
- **読者の感想の管理**: 誹謗中傷・名誉毀損・個人情報の投稿リスク。確認・通報・削除の手段、文字数上限、NGワードを用意する
- **収益化**: 広告・アフィリエイト・有料化を入れると、他人の記事の利用と受け取られやすい。入れる場合は再確認
- **保存するデータ**: 他人の記事の本文・タイトル・サムネイル・いいね数を自前のDB(Notion / D1)に複製しない。保持するのは URL と自分の入力だけ(カード表示は公式の埋め込みに任せる)
- **note の API・スクレイピングは使わない**: `robots.txt` が `/api/*` を全クローラーに Disallow
- **記事の削除・非公開**: 埋め込みがエラー表示になるため、一覧から除く確認手段を用意する
- **サーバー負荷**: 件数が増えたらページ分割と遅延読み込みを維持
- **規約の改定頻度**: 規約は頻繁に改定される。公開前と定期的に再確認

### 公開前に決めること・注意点

- **読者の入力の安全性**: 誰でも送れるため、スパム対策(Cloudflare Turnstile、レート制限)、文字数・金額の上限チェック、感想の表示時のエスケープが必要。金額は自己申告で、実際に note で購入した保証はない(表示でもそう分かるようにする)
- **読者の感想の公開範囲・個人情報**: 名前は任意入力。投稿の削除手段(サイト主が D1 などで削除)を用意する
- **パズル**: 現状は「サイト主の感想数 + 読者の感想数」(デモ分を含む)で埋まるピース数が決まり、この端末での入力分だけが加わる。D1 に移したあとは、全員分の感想数が反映される
